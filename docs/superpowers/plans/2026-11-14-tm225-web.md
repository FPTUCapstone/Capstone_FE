## Proposed integration DTOs for parent / Halley

- POST /api/v1/admin/staff-accounts, Administrator, body {fullName,email,phoneNumber}.
- POST /api/v1/admin/service-provider-accounts, Staff, body {fullName,email,phoneNumber,businessName,category,linkedPoiIds}. category is Hotel, VehicleRental or Restaurant.
- GET /api/v1/admin/service-provider-accounts/available-pois, Staff. Items {id,code,name,category,address,status}.
- Provisioning response data {userId,email,fullName,role,status,mustChangePassword,messageCode}. No credential fields.
- GET /api/v1/provider/service-booking-requests with status,startDate,endDate,keyword,page,pageSize. Response data {items,totalCount,page,pageSize}. Sort PendingConfirmation first, requestedDate ascending, id ascending.
- GET /api/v1/provider/service-booking-requests/{id}. Data matches BookingRequestItem from source UI, including contact and server timestamps.
- POST .../{id}/decision with {action:Confirm|Reject,rejectionReason?}.
- POST .../{id}/outcome with {outcome:Completed|NoShow,actualAmount?}.
- Both mutations forward Idempotency-Key unchanged. Return authoritative BookingRequestItem in data. Retry identical payload with identical key after uncertain transport failure.
- Authentication returns role ServiceProvider and boolean mustChangePassword. Existing web/change-password returns replacement auth context after successful change.
